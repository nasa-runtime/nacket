# 关闭与持久任务责任

[English](shutdown.en.md)

nacket 使用 napp 的统一关闭流程和 `application.shutdown_timeout_ms`。停止接流、关闭会话、撤销路由资格、结束 broker 消费、注销发现记录和释放实际资源是不同步骤；没有确认的步骤不能报告成功。

每个产品路由门禁共享节点永久终止标志。停止节点时先发布该标志，不等待配置、路由目录或数据卷锁。已有写出许可也复验该标志；已经开始的完整包可能需要结束或关闭传输，实际 writer 责任不会因设置标志提前消失。迟到配置或控制回复即使完成落盘，也不能在已经终止的节点重新开放业务。

数据卷提交使用有界持久任务目录，最多同时保留 32 个真实阻塞任务；本地代理断言提交另受最多 16 个并发的限制。路由提交、集群定义准备、控制高水位和断言消费均把容量、数据卷引用以及必要串行锁移交给实际阻塞任务。HTTP 超时、会话关闭或异步等待取消都不能提前归还这些责任。

路由修改按独立编辑锁串行，先保护受影响旧门禁，再持久提交，再发布完整冻结快照。持久 I/O 不占用供准入、观察和配置读取使用的目录写锁或配置锁。控制高水位读取继续按原序列串行，等待取消不能使旧落盘与后续观察交叉。

数据卷 owner 在宿主关闭时同步拒绝新任务，并在宿主原始截止点内等待真实工作结束。超时报告 `socket persistence drain incomplete`；实际任务仍保留数据卷引用与独占文件锁，不声称已经撤销落盘，也不提前允许另一个进程使用同一数据卷。napp 入口退出时使用其已有的运行时关闭行为；容器编排应留出大于应用关闭预算的终止宽限期。强制终止后的恢复只读取已经确认的正式记录，并重新验证控制权威和高水位。

已经进入真实文件写入的提交可能在等待者取消后完成。重新启动须读取正式账本并使用其中的有效 revision；
旧配置不能覆盖较新的持久定义。待决临时文件不是已提交事实，普通文件校验、原子替换与数据卷独占仍然有效。
节点永久终止标志保证晚到的落盘结果不能使已关闭进程重新取得业务资格。

`nacket_runtime_state{state="persistence_jobs"}` 显示尚未结束的真实持久任务，包括已经失去等待者的任务。最终退出后的指标不保证送达，关闭错误同时通过 nalog 和进程退出结果体现。状态通知、生命周期回调及 broker 提交各自保留其交付边界；断线本身不证明终端收到关闭通知。
